# Train Supernet Script Generation Workflow

Use this workflow for `<output_dir>/supernet.py` to generate `<output_dir>/train_supernet.py`, `<output_dir>/run_train_supernet.sh`, and any small helper files needed by the generated training workflow. Do not start training locally.

The goal is to produce a project-specific supernet training entry point under a **fixed training paradigm**: knowledge distillation from a frozen pretrained original-model teacher. Reuse the user's real dataset loading and evaluation conventions; the training loop itself is generated by this workflow — teacher forward under `no_grad`, loss = per-slot hidden cosine + final-logits KL, only variant-branch parameters train, and each optimizer step uses exactly one sampled per-slot choice path. There is no per-project training-paradigm decision, and the objective contains no task/supervised loss term (pure KD).

## Source Evidence

Build the script from the Step 1 project context, the user's own data and evaluation code, and the `<output_dir>/supernet.py` and `<output_dir>/inspect_supernet.py`. The generated script must follow the user's dataset, preprocessing, batch format, model-call signature, evaluation, and runtime conventions. The training loss and optimizer are this workflow's fixed recipe, not ports of the user's training code.

Use `<output_dir>/project_manifest.md` to navigate the user's code: read the specific files under `<user_project_root>` it points to instead of bulk-reading the project, and when a needed detail is missing from the manifest or looks inaccurate, explore `<user_project_root>` (targeted) and update the manifest in place, since source code is always authoritative. Refer to the generated `supernet.py` and `inspect_supernet.py` for supernet construction and sampling constraints. The inspector enumerates each transformer layer slot, its branch set, and the all-original path; all choice-path construction in the training script must follow the same slot enumeration and branch names.

Generated artifacts must be self-contained for project-specific code. Do not import modules from the **user's project** (`<user_project_root>`). Copy and adapt any required project logic into `train_supernet.py` or helper files under `<output_dir>`. Apart from the Python standard library, installed third-party packages, and `nas_agent`, generated artifacts should import only files under `<output_dir>`.

### Ported Helper Files

When the calling skill delegated porting to `project-porter` subagents, the ported helper files already exist under `<output_dir>`: import them as siblings and write call sites against the porter's API report instead of re-porting. Interface mismatches are resolved in this workflow as they surface: adapt your call sites or edit the helper files directly, never add wrapper layers. When touching ported logic (formulas, control flow, constants), preserve the original project's semantics.

### Pretrained Checkpoint Loader (`load_pretrained.py`)

`<output_dir>/load_pretrained.py` is the pipeline's deterministic pretrained-checkpoint loader (an upstream artifact already present in this artifacts directory). It exposes `build_pretrained_model()`: returns the pretrained original model instance with `{{ inputs.pretrained_ckpt }}` weights loaded (checkpoint wrappers unwrapped, DataParallel prefixes stripped, keys matched strictly against the original model), and accepts an optional `device=` keyword.

`train_supernet.py` must consume it as the single construction path for:

- the **teacher** — an independent frozen instance of the pretrained original model, never extracted from the supernet and never modified;
- the **weight-inheritance reference** for the startup assertions — original-branch parameters are compared against the teacher's parameters, which carry the checkpoint values.

Never re-implement checkpoint unwrapping or prefix-stripping inline, and never bypass this loader with a raw `torch.load` + `load_state_dict` against the user's checkpoint format.

## Generation Rules

Write the generated training script with these sections and contracts.

### 1. CLI And Runtime Args

Use a stable base CLI for NAS training runtime:

- `--output_dir`: Default `"runs/train"`; all checkpoints (`supernet_latest.pth`, `supernet_best.pth`, progress snapshots) and training logs are written here
- `--eval_interval`: Evaluation frequency measured in the generated script's chosen training progress unit
- `--device`: Default `"auto"`, allow choices `["auto", "cuda", "npu", "cpu"]`
- `--amp`: Enable AMP (Automatic Mixed Precision)
- `--lr`: Learning rate; default from the user's original training config as the starting point
- `--max_grad_norm`
- `--pretrained_ckpt`: path to the pretrained original-model checkpoint; teacher construction and the weight-inheritance assertions both consume it (via `load_pretrained.py`)
- `--max_train_steps`: Global optimizer-step budget cap (counts every optimizer step regardless of epoch-vs-step progress unit); default `0` = unlimited. When `> 0`, the training loop short-circuits the moment `global_step >= max_train_steps`: break out of the batch loop, still run the end-of-progress-unit eval + checkpoint for the partial progress unit, then break the outer loop. This cap is mandatory to support CPU/CI runs whose full schedule would take many hours; it is orthogonal to `--epochs`/`--max_steps` (the horizon) and composes with them. Expose it in the launcher as `MAX_TRAIN_STEPS` (default `0`) so operators can bound a run without editing the horizon.
- `--progress-every`: progress.jsonl chart-feed granularity in optimizer steps (default `50`; `1` = every step). The feed appends a line every N steps **and mandatorily at every progress-unit boundary** (see §3(b)) — a per-epoch-only feed yields a curve too sparse to watch live.
- `--seed`

KD recipe arguments (fixed recipe, see §8):

- `--kd_hidden_weight`: weight of the per-slot hidden cosine term; default `1.0`
- `--kd_logits_weight`: weight of the final-logits KL term; default `1.0`
- `--kd_temperature`: temperature for the logits KL term, exposed for override with a sensible default (only when the chosen KL helper accepts a temperature)

Expose project-derived training and runtime arguments from the user's project, such as dataset/config paths, training budget, batch size, worker count, augmentation flags, validation controls, and task options. Preserve the user's defaults where they exist, but allow CLI overrides for remote runs.

### 2. Distributed Setup

The **default launcher is single-process `python3`** (no torchrun, no DDP wrap). When launched with `torchrun --nproc_per_node=N` (multi-GPU), `RANK` env is present → `is_distributed()=True` → DDP wrap activates automatically.

Do not infer the target GPU/NPU runtime from the current machine. The generated script is intended for a remote training server, so device and backend selection must remain runtime-configurable through the launcher, environment, and `nas_agent.train`.

**Single-device path (default):** plain `python3 train_supernet.py` (no `RANK` env) → `setup_distributed()` does **not** `init_process_group` → `is_distributed()=False` → `get_world_size()=1` / `is_main_process()=True` / `barrier()` no-op.

**Multi-GPU path (when `torchrun` used):** `RANK` env present → `setup_distributed()` calls `init_process_group` → `is_distributed()=True` → DDP wrap, `DistributedSampler`, `all_reduce` all active.

Use `nas_agent.train.distributed` to configure distributed setup, device resolution, DDP-safe helpers, and AMP.

**DDP wrap is conditional (when `is_distributed()`):** Only wrap in `DistributedDataParallel` when `is_distributed()` returns True. On single-device, skip DDP entirely—this eliminates DDP footguns (unwrap ordering, `all_reduce` sequencing, `DistributedSampler.set_epoch`, `find_unused_parameters`, `save_checkpoint_ddp` barrier, arch-sampling sync).

**DDP unwrap rule (when `is_distributed()`):** `DistributedDataParallel` delegates all standard `nn.Module` methods (`forward()`, i.e. `model(x)`, `parameters()`, `train()`, `eval()`, `state_dict()`, `zero_grad()`, etc.), so calling them on the DDP-wrapped model works directly without unwrapping. Only custom attributes and methods defined by the supernet (e.g. `search_space`, `get_active_subnet()`) require `unwrap_model()` to access the inner module. In practice, the most frequent NAS-specific call in the training loop is `set_sample_config`, which `set_sample_config_ddp()` already handles; manual `unwrap_model()` is only needed for occasional access outside the training loop such as reading `search_space` or extracting a subnet.

**AMP usage rule:** Use `autocast()` and `grad_scaler()` from `nas_agent.train.distributed` for AMP; they prefer PyTorch native `torch.amp` APIs for CUDA and NPU. Keep the autocast enable flag independent from `scaler.is_enabled()`. Use the user's AMP setting directly, e.g. `autocast(device, enabled=args.amp)`. `GradScaler` may be disabled on some devices (especially NPU where bf16 autocast is used without scaling), but autocast should still follow the user's AMP setting. `autocast(device, enabled=False)` is a nullcontext—orthogonal to single-device.

Use this template unless the user's project has stricter distributed or model-access conventions that must be preserved:

```python
from nas_agent.train.distributed import (
    autocast,
    get_local_rank,
    get_rank,
    grad_scaler,
    is_distributed,
    is_main_process,
    set_sample_config_ddp,
    setup_distributed,
    torch_manual_seed,
    unwrap_model,
)
from torch.nn.parallel import DistributedDataParallel


device = setup_distributed(args.device)
torch_manual_seed(args.seed + get_rank())
scaler = grad_scaler(device, enabled=args.amp)

model = model.to(device)

# optimizer and scheduler go here, before DDP wrapping.
# The optimizer covers ONLY the trainable variant-branch parameters (freeze
# grouping from §5); never pass bare model.parameters(). AdamW is the default
# recipe; --lr is exposed for override.
trainable_params = [p for p in model.parameters() if p.requires_grad]
optimizer = optim.AdamW(trainable_params, lr=args.lr)

# DDP wrap is conditional: only when torchrun sets RANK env → is_distributed()=True.
# Single-device (plain python): skip DDP entirely.
if is_distributed():
    device_ids = None if device.type == "cpu" else [get_local_rank()]
    model = DistributedDataParallel(
        model,
        device_ids=device_ids,
        find_unused_parameters=True,
    )

...

# Standard nn.Module methods (forward, parameters, train, ...) work on the
# DDP-wrapped model directly.  Only supernet-specific members need unwrap.
output = model(data)                               # forward → no unwrap needed
set_sample_config_ddp(model, arch_config)          # handles unwrap internally
subnet = unwrap_model(model).get_active_subnet()   # custom method → unwrap
search_space = unwrap_model(model).search_space     # custom attribute → unwrap
```

Note: Keep `find_unused_parameters=True` for DDP-wrapped supernets because each sampled choice path activates only one branch per slot, so the unsampled branch parameters do not contribute to the current loss.

### 3. Progress Driver

First choose the generated script's training progress unit from the user's project. Use epochs only when the original training code and data pipeline are naturally epoch-based. Otherwise, use optimizer update count, stored as `global_step`.

Use that same progress unit consistently for the training horizon, `--eval_interval`, scheduler stepping, checkpoint save interval, logging interval, and final validation. Do not force streaming or iterable inputs into artificial epochs just to match common image-classification scripts.

Do **not** port the user's complex logging frameworks (e.g. WandB, TensorBoard, custom file loggers). Instead, use the simple standard output (stdout) progress tracking described below. You may refer to basic logging parameters from the original project (e.g. `args.log_interval`) if applicable.

Provide real-time training progress via periodic batch-level logging (rank 0 only) inside the training loop. Without batch-level logs, a long-running epoch produces no output and makes it impossible to tell whether training is progressing or hung (especially when the dataset is large, the model forward is expensive, or the per-step teacher + student double forward multiplies the cost).
- **Primary approach (`tqdm`)**: Use `tqdm` progress bars via `disable=not is_main_process()`. For epoch-based training, wrap the batch iterator so each epoch displays a per-batch progress bar. For step-based training without an epoch concept, use a single `tqdm` bar tracking `global_step` up to the total training horizon. Include running metrics (e.g. `kd_loss`, learning rate) in the bar's `postfix` or `description`.
- **Fallback approach (`print`)**: If the user's original project environment is not suitable for `tqdm`, use a periodic `print` statement (e.g. `if global_step % args.log_interval == 0:`) instead.

**CRITICAL — machine-parseable progress (contract, mandatory)**. On top of the human-readable progress above, the generated script **must** emit **two** machine feeds per completed progress unit (rank 0 only). Both are required — they serve different downstream consumers. Training-loop metric names are fixed by the KD recipe (`kd_hidden_loss` / `kd_logits_loss` / `kd_loss`); evaluation metrics keep the user's real names (§9).

**(a) Telemetry line (stdout)** — consumed by `psu_run_train` ETA / health / progress watchers (line-oriented, structurally regex-parsed). Print exactly one line per progress unit:
- epoch-based: `epoch <cur>/<total> kd_loss <value>` — e.g. `epoch 3/10 kd_loss 0.4521`
- step-based: `step <cur>/<total> kd_loss <value>` — e.g. `step 1200/6000 kd_loss 0.4521`

`<cur>` starts at 1, `<total>` is the full horizon, `<value>` is a plain float, and the primary metric is the fixed recipe's total KD loss under the name `kd_loss` (the sum `kd_hidden_weight * hidden_term + kd_logits_weight * logits_term`). The downstream consumers parse this line structurally (`(epoch|step)` token + `<n>/<n>` fraction + a single name token + a trailing numeric value).

A `tqdm` bar alone does **not** satisfy the contract — the plain `epoch`/`step` line must be printed to stdout once per progress unit (e.g. via the same gated `print()` that updates the bar). Do not print other lines that contain the bare words `epoch`/`step` followed by digits in a different meaning (e.g. "epoch:3/10", "Epoch 3", or a save message like "saved supernet_epoch_0005.pth" — use "checkpoint epoch 5 saved" or a bracketed form instead) so the downstream regex (`(epoch|step)[^0-9]*[0-9]+`) cannot misparse. Expose the horizon as `--epochs N` (epoch-based) or `--max_steps N` (step-based) so downstream can read the total from the launcher script.

**(b) Progress JSONL (chart feed)** — consumed by `psu_run_train`'s live chart watcher (record-oriented, JSON-parsed; pushes every metric below to the frontend as a live multi-series curve). Append one JSON line **every N optimizer steps** (`--progress-every`, default `50`) **and mandatorily at every progress-unit boundary** (epoch/step end, including the final partial unit) to `$ORCA_ARTIFACTS_DIR/runs/train/progress.jsonl`:

```
{"step": <global_step>, "metrics": {"<name>": <float>, ...}}
```

- Write granularity is **step-level, not per progress unit**: a per-epoch-only feed (e.g. 5 epochs → 5 points) is too sparse for a live convergence curve. Every N steps, at the end of each progress unit, and once at training end, append one line (`1` via `--progress-every` = every step for short runs).
- `step` = the global optimizer-step count at write time (int) — monotonically increasing across the whole run, including the boundary lines.
- `metrics` = **every scalar metric accumulated since the last written line** — the KD recipe terms (`kd_hidden_loss`, `kd_logits_loss`, `kd_loss`) as running means over the window plus the instantaneous `lr`; on lines written at evaluation points, also the validation metrics under the user's real names plus the §9 aggregates (`val_<metric>_kpath_mean`, `val_<metric>_all_original`). The chart plots each metric as its own series, so omitting a metric hides it from the user.
- Open in append mode, write `json.dumps(row) + "\n"`, `flush()` after each write, and guard the write with `if is_main_process()`. The launcher truncates this file at the start of each attempt, so each attempt starts fresh.

**CRITICAL: Guard all single-writer side effects with `if is_main_process()` so only rank 0 performs them.** Failure to do so causes race conditions or duplicate outputs across ranks. Operations that require this guard include:

- **Logging**: `print()` statements, `tqdm` output, and any metric reporting
- **File writes**: any file output during training
  - Exception: `save_checkpoint_ddp()` does **not** need this guard. It already handles rank-gating and barriers internally (see Checkpoint section).
- **Directory creation**: `os.makedirs()` for output directories, log directories, etc.

**CRITICAL: Separate metric computation from logging.** `AverageMeter.avg` (returns `float`, not tensor) triggers `dist.all_reduce`, a collective operation that all ranks must call together. Compute `.avg` on all ranks first, then gate only the `print()` / `tqdm` / file-write on `is_main_process()`. See §9 Evaluation, DDP Metric Aggregation for the full rule, correct pattern, and anti-patterns.

When training data is sharded across ranks, metrics logged during training (kd_loss, etc.) must also be aggregated across ranks via `AverageMeter` so that `tqdm` or `print` displays globally correct values.

### 4. Data Pipeline

Port the user's real data semantics: dataset builders, transforms/tokenizers, collate function, batch structure, model-call inputs, labels, masks, and metadata. When `is_distributed()` (torchrun multi-GPU), adapt sampler, dataloader, seeding, and metric reduction for distributed training. For map-style datasets under DDP, ensure `DistributedSampler` is used and `sampler.set_epoch(epoch)` is called at the beginning of each epoch. For iterable or streaming datasets under DDP, ensure data is sharded correctly across workers and ranks. On single-device (default), use a plain sampler—no `DistributedSampler` needed.

Prefer decoupling dataset and data-loading logic (dataset class, transforms, collate function, metric helpers, data-loading utilities) into a separate helper file (e.g. `dataset.py` or `data_utils.py`) under `<output_dir>`, keeping the training entry point focused on the training loop. Inline data logic in the training script only when it is trivially short.

Keep validation metrics and best-metric direction aligned with the user's original code unless distributed execution requires a mechanical adjustment. (The training objective is the fixed KD recipe and does not port the user's supervised loss.)

Expose dataset paths as CLI arguments (e.g. `--data_dir`), not hardcoded literals. When the user's data path under `<user_project_root>` can be identified, use its absolute path as the default. All generated data-loading functions must accept data paths as parameters; do not hardcode or derive paths from package locations inside function bodies.

#### DataLoader Launch Hygiene (mandatory)

On CUDA/NPU training boxes, a DataLoader with `num_workers>0` forks child processes; if the parent has already initialized CUDA, the forked workers crash (`CUDA initialization error`). `pin_memory=True` additionally errors on CUDA tensors (`CUDA tensors cannot be pinned`).

- **`num_workers=0` by default**: all generated DataLoaders must default to zero worker processes (no forking). The launcher exposes `NUM_WORKERS` as an editable variable with default `0`; do not change this default. Only raise it when spawn-based parallelism is verified to work, with justification.
- **`pin_memory=False`**: all generated DataLoaders must pass `pin_memory=False`; do not enable pin memory.
- Both values are part of the launch contract, not style choices — a training run that dies early on fork/pin errors burns the attempt budget.

### 5. Model Construction And Weight Inheritance

Import `SearchSpace`, `ArchConfig`, and `SuperNet` from the generated `supernet.py` as a plain sibling import, eg: `from supernet import ArchConfig, SearchSpace, SuperNet`.

Instantiate `SearchSpace()` and `SuperNet(...)` using the generated constructor signature. Pass model-construction arguments (e.g. `num_classes`, `action_dim`) via the constructor, using values from the user's original project.

```python
search_space = SearchSpace()
model = SuperNet(search_space, num_classes=args.num_classes, ...)
```

#### Weight Inheritance And Freeze Grouping (fixed)

- **original branches inherit the parent weights**: the supernet's original branches carry the pretrained checkpoint values. The inheritance source is the `load_pretrained.py` asset (the same loader the teacher uses) — do not hand-roll a second loading path.
- **variant branches keep their random initialization**.
- **freeze grouping**: original branches and all non-slot modules are frozen via `requires_grad_(False)`; only variant-branch parameters remain trainable. Apply the grouping through the mechanism `supernet.py` exposes (its slot/original-module registries or a freeze helper); the invariant is that after construction, **exactly the variant-branch parameters have `requires_grad=True`**:

```python
# Illustrative — adapt to the freeze mechanism supernet.py exposes:
for p in original_branch_and_non_slot_parameters(model):
    p.requires_grad_(False)
trainable_params = [p for p in model.parameters() if p.requires_grad]
assert trainable_params  # variant-branch parameters must exist and be trainable
```

#### Teacher (independent frozen instance)

```python
from load_pretrained import build_pretrained_model

teacher = build_pretrained_model(device=device)
teacher.eval()
for p in teacher.parameters():
    p.requires_grad_(False)
```

The teacher is never extracted from the supernet and never modified by any injection seam. Teacher forwards run only inside `torch.no_grad()`.

#### Startup Deterministic Assertions (fail loud, before the training loop)

1. **Original-branch inheritance spot-check**: for a deterministic sample of (slot, parameter) pairs across original branches, assert `torch.allclose(original_branch_param.detach().cpu(), teacher_param.detach().cpu())` — the teacher carries the checkpoint values, so any mismatch means the inheritance silently dropped or misaligned weights. Print the compared keys (rank 0); on mismatch, raise with the list of mismatched entries (fail loud — never warn-and-continue).
2. **Teacher forward smoke**: one `torch.no_grad()` teacher forward on a dummy batch shaped by the data pipeline — catches device/dtype wiring errors before hours of training.

Run both on every rank (they are device-dependent), gate only the printing on `is_main_process()`.

### 6. Optimizer, Scheduler, AMP, And Gradient Clipping

The optimizer covers **only the trainable variant-branch parameters** (the filtered list from §5). Passing bare `model.parameters()` to an optimizer is a contract violation — it would push frozen original-branch and non-slot parameters into the optimizer and defeat the freeze grouping. Default recipe: `optim.AdamW(trainable_params, lr=args.lr)`.

The scheduler (if any) is recipe-owned: its step granularity must fit the chosen progress unit and its total steps/epochs must match the training budget (see Validation).

Use the user's original training budget as the **starting point** for the training budget (total epochs or optimizer steps) and tune for convergence — each optimizer step costs one student path forward plus one teacher `no_grad` forward. There is no fixed budget multiplier; when the budget is set, adjust budget-dependent hyperparameters (scheduler totals, decay milestones, etc.) accordingly.

#### Batch Size & Learning Rate

`--batch_size` is per-device. Under DDP the effective batch size is `batch_size * world_size`.

Use the user's original LR as the `--lr` default and pass `args.lr` directly to the optimizer. If the user's original training code already runs under DDP and includes an explicit LR scaling rule (e.g. linear scaling with world size), reuse that rule.

#### Gradient Clipping

Add `--max_grad_norm` as a stable numeric CLI argument with default `1.0`. When `--max_grad_norm > 0`, call `torch.nn.utils.clip_grad_norm_(model.parameters(), args.max_grad_norm)` after the per-path KD loss has called `backward()` and before the optimizer step. If AMP scaling is enabled, call `scaler.unscale_(optimizer)` before clipping.

#### NPU Compatibility: Disable `foreach` Optimizations

Huawei Ascend NPU does not support PyTorch's `foreach`-based multi-tensor optimization. In practice, the `foreach` parameter appears in two places in the training loop: optimizer constructors (`torch.optim.*`) and gradient clipping utilities (`clip_grad_norm_`, `clip_grad_value_`). When the resolved device type is `"npu"`, pass `foreach=False` to both. Determine `is_npu` once after `setup_distributed()` resolves the device and reuse it:

```python
is_npu = device.type == "npu"
```

For example:

```python
# Optimizer constructor
optimizer = optim.AdamW(trainable_params, ..., foreach=False if is_npu else None)

# Gradient clipping utility
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm, foreach=False if is_npu else None)
```

### 7. Checkpoint

Save `supernet_latest.pth` whenever the generated script is scheduled to save a checkpoint. Use progress-specific snapshot names, such as `supernet_epoch_<epoch:04d>.pth` for epoch-based training or `supernet_step_<global_step:08d>.pth` for step-based training. Save `supernet_best.pth` when the **K-path mean** validation metric improves (see Evaluation). Expose a CLI parameter (e.g. `--save_interval`) to control how often intermediate snapshots are saved and set a reasonable default.

Note: When evaluation is also scheduled for the same epoch/step, save `supernet_latest.pth` **after** evaluation and `best_metric` update, so that `best_metric` in the checkpoint reflects the most recent result.

**Full-module state_dict contract (mandatory)**: the supernet checkpoint stores the **full module state_dict — frozen parameters included** (original branches + non-slot modules + variant branches). Filtering the state_dict by `requires_grad` when saving is forbidden: the downstream search evaluator loads this checkpoint with strict key matching, and a filtered checkpoint fails loud or silently under-represents the supernet. `save_checkpoint_ddp` serializes `model.state_dict()` whole and satisfies this contract.

Use `save_checkpoint_ddp` from `nas_agent.train` for all checkpoint writes. It automatically unwraps `DistributedDataParallel` (clean state-dict keys), gates the write on rank 0, and barriers other ranks. `save_checkpoint_ddp` forwards its keyword arguments to `save_checkpoint`; `epoch`, `global_step`, `best_metric`, and `args` are optional but should be included whenever the training context tracks them.

Do **not** wrap `save_checkpoint_ddp()` inside `if is_main_process()`. The function contains an internal `barrier()` that all ranks must reach; wrapping it in a rank guard causes a multi-GPU deadlock.

```python
from nas_agent.train import save_checkpoint_ddp

# ── Anti-pattern (causes multi-GPU deadlock) ──
# if is_main_process():
#     save_checkpoint_ddp(...)

# ── Save (inside training loop / after evaluation) ──
save_checkpoint_ddp(
    os.path.join(args.output_dir, "supernet_latest.pth"),
    model,
    optimizer=optimizer,
    scheduler=scheduler,
    scaler=scaler,
    epoch=epoch,
    global_step=global_step,
    best_metric=best_metric,
    args=vars(args),
    # extra={"sampler_state": ...},  # optional project-specific state
)
```

### 8. KD Training Loop (fixed recipe)

KD is the **fixed training paradigm** of this pipeline — always enabled, with no per-project enable/disable decision and no delayed-start scheduling. The teacher is a pretrained frozen model, so distillation is well-defined from step 0.

#### Teacher

An independent frozen instance of the pretrained original model, built via `load_pretrained.py`'s `build_pretrained_model()` (see §5): `teacher.eval()`, all teacher parameters `requires_grad_(False)`, and teacher forwards run only inside `torch.no_grad()`.

#### Loss Composition (pure KD)

```text
kd_loss = kd_hidden_weight * hidden_term + kd_logits_weight * logits_term
```

- **hidden_term** = mean over slots of `cosine_kd_loss(student_hidden[s], teacher_hidden[s])` — cosine similarity is scale-invariant, measuring directional agreement of per-slot layer outputs.
- **logits_term** = `logits_kd_loss(student_outputs, teacher_outputs, temperature=args.kd_temperature)` on the final task-level outputs, guarded by a runtime shape check (`student_outputs.shape == teacher_outputs.shape`).

Use the `cosine_kd_loss` / `logits_kd_loss` helpers from `nas_agent.train.distillation`. **Pure KD declaration**: the objective contains **no task/supervised loss term** — the user's original training loss is not ported into the training objective. The user's evaluation measure remains the sole authority for evaluation and best-checkpoint selection (§9).

#### Why per-slot hidden distillation is sound here (declared basis)

Hidden-state KD is generally unsafe when teacher and student disagree on internal layer topology — it would require adapters, intermediate feature matching, or layer-to-layer mapping engineering, which this pipeline forbids. That concern does not apply to this teacher: it is the **same-topology parent model** of the supernet — every slot's original branch **is** the parent's layer, so teacher and student layer outputs align slot-by-slot by construction and no adapters are involved. Per-slot hidden cosine is therefore a **declared, first-class component of the fixed recipe**, not a deviation; do not flag it as forbidden feature-level KD and do not replace it with a final-output-only loss.

#### Hidden Hook Alignment (fail loud)

Teacher hook points and student slot capture points must be driven by **one canonical slot list** — the same slot enumeration the supernet and inspector expose:

- Build the canonical slot list once (e.g. from `search_space`'s slot enumeration).
- Register the teacher's layer-output hooks and the student's slot-output hooks by iterating that **single** list.
- Before training, assert `len(teacher_hiddens) == len(student_hiddens) == len(slots)` and pair hidden states by slot index.
- Any count/shape mismatch → raise at startup with the mismatched slot indices. A misaligned-by-one-layer KD silently learns the wrong pairing while the loss still decreases — this must fail loud, never warn-and-continue.

#### Choice Sampling

Write small local sampling helpers in `train_supernet.py`; do not import `inspect_supernet.py` directly. The **only** sampled dimension is the per-slot branch **choice**: depth and all layer dimensions are pinned to the original model's values and are never sampled.

Implement `sample_choice_path(search_space, rng)` as a local helper that returns one choice-only `ArchConfig`: for each transformer layer slot, sample one branch from that slot's branch set. Use the slot's actual branch list from the search space (canonical order: `original`, `vanilla`, `random_synthesizer`, `relu_attention`, `fnet`, `softs_star`) — never a hardcoded copy of the branch names.

Simplified example (adapt to the generated `SearchSpace` / `ArchConfig` signatures):

```python
def sample_choice_path(search_space, rng):
    """Sample one per-slot choice path; the choice dimension is the only sampled dim."""
    # canonical SearchSpace shape: branch_choices is a flat branch-name tuple shared
    # by every slot, depth is the slot count, ArchConfig.choices is a per-slot tuple.
    return ArchConfig(
        choices=tuple(rng.choice(search_space.branch_choices) for _ in range(search_space.depth))
    )
```

All randomness inside `sample_choice_path` must use the provided local `rng`, not global Python or PyTorch RNG state. The sampled config must be accepted by `set_sample_config` (choice-only config; no depth or layer-dimension fields).

#### Training Example

For each training batch: sample one choice path, set it on the supernet, run the teacher forward once under `no_grad`, run the student path forward, compute the KD loss, call `backward()` once, clip, step. One optimizer step trains exactly one sampled path.

**DDP path-sampling constraint:** In distributed training every rank must activate the exact same choice path on every forward pass; otherwise DDP's gradient all-reduce will mix gradients from different architectures and corrupt training. Use `sync_random_seed` (broadcast a seed from rank 0) so that all ranks produce identical per-slot choices from the same `rng` state each iteration.

The example below is a distributed and AMP-aware single-path KD training template for the inner training loop. Adapt task-specific batch unpacking, model call, and scheduler timing to the user's project (the KD objective consumes only the model inputs; labels are used by evaluation, not by the training loss).

```python
import random

import torch
import torch.distributed as dist

from nas_agent.train import (
    autocast,
    cosine_kd_loss,
    is_distributed,
    is_main_process,
    logits_kd_loss,
    set_sample_config_ddp,
)
from load_pretrained import build_pretrained_model


def sync_random_seed(device):
    """Single-device: local random seed; multi-GPU: broadcast rank0 seed."""
    if not is_distributed():
        return random.SystemRandom().randrange(0, 2**31)
    seed_source = random.SystemRandom()
    seed_tensor = torch.empty((), dtype=torch.long, device=device)
    if is_main_process():
        seed_tensor.fill_(seed_source.randrange(0, 2**31))
    dist.broadcast(seed_tensor, src=0)
    return int(seed_tensor.item())


# ── Teacher (built once, frozen) + canonical slot hooks (built once, aligned) ──
teacher = build_pretrained_model(device=device)
teacher.eval()
for p in teacher.parameters():
    p.requires_grad_(False)

slots = canonical_slot_list(search_space)      # from supernet.py / search_space
teacher_hiddens = register_teacher_hooks(teacher, slots)
student_hiddens = register_student_hooks(model, slots)
assert len(teacher_hiddens) == len(student_hiddens) == len(slots)  # fail loud on misalignment

model.train()
for batch in train_loader:
    inputs, _targets = batch  # pure KD: the training loss does not consume labels
    inputs = inputs.to(device, non_blocking=True)
    optimizer.zero_grad(set_to_none=True)

    arch_seed = sync_random_seed(device)
    arch_rng = random.Random(arch_seed)
    path_config = sample_choice_path(search_space, arch_rng)
    set_sample_config_ddp(model, path_config)

    teacher_hiddens.clear()
    student_hiddens.clear()
    with torch.no_grad():
        teacher_outputs = teacher(inputs)

    with autocast(device, enabled=args.amp):
        student_outputs = model(inputs)
        hidden_term = sum(
            cosine_kd_loss(student_hiddens[i], teacher_hiddens[i].detach())
            for i in range(len(slots))
        ) / len(slots)
        if student_outputs.shape != teacher_outputs.shape:
            raise ValueError(
                f"teacher/student output shape mismatch: "
                f"{teacher_outputs.shape} vs {student_outputs.shape}"
            )
        logits_term = logits_kd_loss(
            student_outputs,
            teacher_outputs.detach(),
            temperature=args.kd_temperature,
        )
        kd_loss = args.kd_hidden_weight * hidden_term + args.kd_logits_weight * logits_term
    scaler.scale(kd_loss).backward()

    if args.max_grad_norm > 0:
        scaler.unscale_(optimizer)
        torch.nn.utils.clip_grad_norm_(
            model.parameters(),
            args.max_grad_norm,
            foreach=False if is_npu else None,
        )
    scaler.step(optimizer)
    scaler.update()
    if scheduler is not None:
        scheduler.step()
    global_step += 1
```

### 9. Evaluation

Run evaluation every `--eval_interval` in the generated script's training progress unit (`epoch` for epoch-based training, otherwise optimizer update count stored as `global_step`), and once at the final training boundary. Evaluation uses the user's ported validation function with the user's real metric; the supernet-ization change is only the choice-path config applied before the forward.

#### K-Path Mean (best-checkpoint basis)

Evaluate the user's validation metric on **K=8 sampled choice paths**, drawn once with a **fixed seed derived from `args.seed`** so the **same path set is evaluated at every eval point** — cross-epoch comparability is the point. The mean of the K metrics is the best-checkpoint selection basis.

#### All-Original Sanity (freeze-violation detector)

Evaluate the **all-original path** separately at every eval point. Its metric must stay ≈ constant across the whole training: the original branches are frozen, so the all-original forward is unchanged by training. **Any drift means the freeze grouping was violated** — log the per-epoch values and treat drift beyond tolerance as a training failure (fail loud), never as a metric to optimize. The all-original value does **not** participate in best-checkpoint selection.

```python
eval_paths = sample_fixed_eval_paths(search_space, k=8, seed=args.seed)  # same paths every eval
all_original = all_original_path(search_space)
path_metrics = []
for cfg in eval_paths:
    set_sample_config_ddp(model, cfg)
    path_metrics.append(run_project_validation(model, val_loader, device))
kpath_mean = sum(path_metrics) / len(path_metrics)
set_sample_config_ddp(model, all_original)
all_original_metric = run_project_validation(model, val_loader, device)
```

(`sample_fixed_eval_paths` / `all_original_path` are local helpers; the fixed seed makes the path set deterministic, and `all_original_path` selects the `original` branch for every slot.)

#### DDP Metric Aggregation (when `is_distributed()`)

When the validation set is sharded across ranks (e.g. via `DistributedSampler`), each rank only sees its own shard, so per-rank metrics are incomplete. Use `AverageMeter` from `nas_agent.train` to accumulate running totals per rank. Reading `.avg` or `.count` triggers `all_reduce` across ranks. `.avg` returns a Python `float` (not a tensor), so any post-processing must use `math` / plain Python operations (e.g. `math.log10`), not `torch.*` ops. On single-device, `AverageMeter.avg` is a no-op (returns local value directly—`all_reduce` is gated by `is_distributed()` in `metrics.py`).

**`update(value, n)` semantics:** it adds `value * n` to the running sum, so `value` must be a **per-sample mean** (e.g. a batch's average loss); passing the batch's already-summed total instead would double-count it. Get this right when reproducing a project's original metric formula defined over the full dataset (not per-batch).

**CRITICAL: `.avg` and `.count` are collective operations.** `all_reduce` requires every rank to participate. Always compute `.avg` on **all ranks** first, then gate only the logging / printing / checkpoint decision on `is_main_process()`. Never place an `.avg` or `.count` call inside an `if is_main_process():` block; doing so causes a multi-GPU deadlock because the non-rank-0 processes never enter the `all_reduce` and hang waiting.

```python
from nas_agent.train import AverageMeter

loss_meter = AverageMeter(device)
acc_meter = AverageMeter(device)

for inputs, targets in val_loader:
    loss = criterion(model(inputs), targets)
    loss_meter.update(loss.item(), n=inputs.shape[0])
    acc_meter.update(acc.item(), n=inputs.shape[0])

# ── Correct: compute on ALL ranks, then gate only the print ──
avg_loss = loss_meter.avg   # all_reduce across ranks
avg_acc = acc_meter.avg     # all_reduce across ranks
if is_main_process():
    print(f"loss={avg_loss:.3e}  acc={avg_acc:.4f}")
```

(Names above are illustrative — use the user's real validation metric names and meters, as enumerated from the user's original evaluation code.)

**Validation metrics flow to the live chart too.** After computing the aggregated validation metrics on rank 0 (the same `is_main_process()` gate), append them to the §3(b) progress JSONL — the K-path mean and the all-original sanity value as separately named entries so cross-epoch drift is observable on the live chart:

```python
if is_main_process():
    with open(os.path.join(args.output_dir, "progress.jsonl"), "a", encoding="utf-8") as f:
        row = {"step": <cur>, "metrics": {
            f"val_{user_metric}_kpath_mean": kpath_mean,
            f"val_{user_metric}_all_original": all_original_metric,
        }}
        f.write(json.dumps(row) + "\n")
        f.flush()
```

`val_<user_metric>` uses the user's real validation metric name (`val_accuracy`, `mAP`, …), never a fabricated `loss`. Omit validation entries on progress units where no evaluation runs.

The following pattern causes a multi-GPU deadlock and must be avoided:

```python
# ── ANTI-PATTERN (causes multi-GPU deadlock) ──
if is_main_process():
    avg_loss = loss_meter.avg   # ← only rank 0 calls all_reduce → HANG
    print(f"loss={avg_loss:.3e}")
```

#### Best Checkpoint Selection

Select `supernet_best.pth` based on the **K-path mean** validation metric (§ K-Path Mean), using the user's own metric direction (e.g. maximize accuracy, F1, mAP; minimize loss, error, WER, perplexity). The K-path mean tracks the quality of the trainable variant branches across the sampled search space, which is exactly what the downstream search consumes; the all-original sanity value is a freeze-violation detector, not a selection signal.

The best-metric comparison must use the globally aggregated metric (from `AverageMeter.avg`) so that all ranks reach the same save-or-skip decision. `save_checkpoint_ddp` contains an internal barrier; if some ranks enter it while others skip, the training deadlocks.
