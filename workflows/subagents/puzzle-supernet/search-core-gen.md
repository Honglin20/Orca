You are a code generation sub-agent. Your sole task: generate 4 files for the search pipeline in `$ORCA_ARTIFACTS_DIR`.

## Choice-Only Search Space (fixed sampling contract)

The search space is choice-only: each transformer layer slot picks one branch. The gene carries one **branch candidate index** per slot — `gene_len = SearchSpace.depth` (the slot count), bounds `[0, len(SearchSpace.branch_choices) - 1]`. Decoding maps each index through `branch_choices[idx]` into `ArchConfig.choices`. There is no depth gene, no padding slot, and no branch-local parameter gene: all dimensions are pinned to the original model's measured values.

## Procedure

1. **Read** `$ORCA_AGENT_RESOURCES/references/workflows/search_supernet_script_generation.md` — authoritative generation contract.
2. **Read** `$ORCA_ARTIFACTS_DIR/search_record_schema.json` — **shared schema**. Every record the fixed search runner's SearchLogger writes to `search_results.jsonl` must match this schema (arch field names, types, metric direction); your evaluator's returned metric keys and the codec's decoded arch feed those records. The `select_architecture.py` (generated by a sibling subagent) will parse rows using the same schema.
3. **Read** `$ORCA_ARTIFACTS_DIR/supernet.py` for SearchSpace / ArchConfig definitions — choice-only: the searchable dimension is `branch_choices` (one branch index per layer slot), the slot count is `SearchSpace.depth`.
4. **Checkpoint path alignment** (critical): evaluator must load the trained supernet ckpt from
   `runs/train/supernet_best.pth` (absolute: `$ORCA_ARTIFACTS_DIR/runs/train/supernet_best.pth`) — produced by the upstream KD training run, loaded with strict key matching.
   `search_config.yaml` must reference this path.
5. **Generate** 4 files:
   - `evaluator.py`: zero-training candidate evaluator — loads the supernet ckpt strictly once, applies each candidate's per-slot choice config via `set_sample_config`, computes the user's validation metric by direct inference, returns smaller-is-better values to the fixed worker (a higher-better metric is negated here — NAS-internal storage/optimization direction only; user-facing output downstream restores the original value and direction, see **User Measurement Authority**; no optimizer / training loop / ckpt writes / teacher / KD loss; does not write `search_results.jsonl` — the fixed search runner's SearchLogger does).
   - `arch_codec.py`: one-way decoder gene → `ArchConfig` (per schema): one branch-index gene per slot, `gene_len` = slot count, bounds `[0, len(branch_choices) - 1]`.
   - `search_config.yaml`: search configuration (latency objective source, budget, paths).
   - `run_search_supernet.sh`: search launcher calling `python3 -m nas_agent.cli.search --config "./search_config.yaml"` with no other CLI arguments (module invocation — no PATH assumption, the `nas-search` console script may not be on PATH; single-device default; **no torchrun**).
6. **Validate**: `python3 -m py_compile evaluator.py arch_codec.py` + `bash -n run_search_supernet.sh`.
