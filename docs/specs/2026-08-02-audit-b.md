## 0. 为什么这是「最结构性」的修复

Orca 的根本承诺（phase-3-events.md §1，铁律 1–4）：

> **单 tape 唯一真相源 + 幂等 reducer + 一条读路径**。
> 即「同一份 tape 重放，必须得到同一状态」——「分歧 = 错误」（§3.4 规则 8）。

本 SPEC 修的三条裂缝都直接破这条铁律：

- **B1**：resume 起点 = `state.current_node`，但 `current_node` 的语义在
  `node_started` / `node_completed` / `route_taken` 三事件的**窗口内**会卡在不一致
  状态，导致 resume 重跑已完成节点——破坏「resume 不重跑 done node」。
- **B2**：live 路径在 `outputs_acc[skipped] = {"output": None, "skipped": True}`
  写了一个**reducer 不持久化**的字段，重放时丢；同一 tape 在 live 与 from_tape
  下渲染出不同视图——直接违 §3.4「分歧 = 错误」。
- **B3**：reducer 对 `agent_usage` 是显式 no-op，docstring 却写「覆盖为最新快照」，
  schema 的 `UsageSummary` 是死字段；文档与代码漂移 + 死字段是噪声源，违反
  「reducer 必须光凭事件序列完整重建状态」的清晰契约。

B 是审计三项里唯一动 reducer 契约的——所以必须先把不变式写死，再讨论方案。

## 1. 背景与根因（每条裂缝怎么破的）

### 1.1 单步事件序列与崩溃窗口

`drive_loop` 单步事件顺序（orchestrator.py:692–720，tape.py 的 append_batch 注释也确认）：

```
node_started(A)  →  node_completed(A){output}  →  route_taken(A→B)
                                                     │
                                  current_node 这里才从 A 翻到 B
```

reducer 对 `current_node` 的更新（replay.py）：

| 事件 | 对 `current_node` 的影响 |
|---|---|
| `node_started`（:140-145） | `current_node = node`（=A） |
| `node_completed`（:147-150） | **不改 `current_node`** |
| `route_taken`（:204-207） | `current_node = data["to"]`（=B） |

→ 窗口 **`[node_completed(A) 落盘, route_taken(A→B) 落盘)`**：state 里
`current_node = A`，但 A 的 `node_status` 已是 `done`、`context[A]` 已有 output。

### 1.2 B1 根因

`Orchestrator.from_tape` 的 resume 起点（orchestrator.py:438）：

```python
resume_node = state.current_node          # ← 窗口内 = A
...
if resume_node is None or resume_node == "$end":
    # 只有 None/$end 时才回退到 done-node 推断
    last_done = cls._find_last_done_node_name(tape, done_nodes)
    resume_node = cls._next_node_for_resume(wf, last_done, outputs_acc)
```

崩在 §1.1 窗口时 `current_node = A`（既非 None 也非 `$end`），**不走兜底分支**，
直接 `resume_node = A` → `_drive_from(A)` → 重跑 A：

- LLM 重派、子进程重跑、外部副作用重发；
- `outputs_acc[A] = {"output": raw_output}` 覆盖原 `context[A]` 的 output（若 LLM
  二次结果不同，下游模板 / route 求值都会跟着漂）；
- `node_started(A)` / `node_completed(A)` 二次落盘（**reducer 幂等**所以 state
  fold 不出错，但「单 tape = 编排史」含两份 A 执行记录，与「resume 不重跑」
  语义矛盾）。

注释自述要兜底的场景（:436-437「tape 末尾正好是 node_completed 但 route_taken
还没 emit」）**正是它出错的场景**——判据错了：判 `current_node` 而不是判
`node_status[A] == "done"`。

### 1.3 B2 根因

skip 分支（orchestrator.py:671）：

```python
outputs_acc[current] = {"output": None, "skipped": True}
```

—— `{"skipped": True}` 是 live 内存里的字段，**reducer 不持久化**：

- reducer 对 `node_skipped` 只设 `node_status[node] = "skipped"`（replay.py:156-158），
  **不写 `context`**；
- `_outputs_acc_from_state`（resume.py:168-175）只对 `state.context.items()` 包壳，
  被 skip 的 node 不在 `state.context` 里 → resume 时 `outputs_acc` 不含该 node。

后果（同一 tape 两视图）：

| 场景 | `outputs_acc[skipped]` | 下游模板 `{{ skipped.output }}`（StrictUndefined） |
|---|---|---|
| live（skip 后立即推进） | `{"output": None, "skipped": True}` | `None`（render 输出 "None"，或经 `\| default` 掩盖） |
| from_tape（resume 后） | **缺失** | `skipped` Undefined → `skipped.output` → **UndefinedError** |

`tests/run/test_skip_to_agent.py:104` 用 `{{ a.output | default('<skipped>') }}`
显式兜底——**掩盖了** live/resume 的分歧，而非覆盖它。删掉这个 `| default`，
resume 路径立即崩，证明分歧真实存在。

### 1.4 B3 根因

reducer 对 `agent_usage` 的实现（replay.py:186-193）：

```python
if t in ("agent_message", "agent_thinking", "agent_tool_call",
         "agent_tool_result", "agent_usage"):
    # ... docstring 自相矛盾：先说「覆盖为最新一次的快照」，再 no-op ...
    return state
```

docstring 写「覆盖为最新快照 / phase 5 的 orchestrator 跨 session 聚合」，但代码
是显式 no-op——**`state.usage` 恒 None**。

无功能 bug（`projections.node_usage` 是独立 batch fold，不依赖 `state.usage`；
`run_manager.py:1953` 读 `state.usage` 时已 None-safe fallback），但有「契约噪声」：

1. docstring 与代码漂移（说一套做一套，违反 Rule 8「Read before you write」的反面）；
2. schema `RunState.usage: UsageSummary | None`（state.py:64）是死的**归集字段**
   （reducer 永不写，唯一读者已 fallback）。**注意（R2）**：`UsageSummary` 类本身
   **非死类**——`projections.node_usage` 用作返回类型 + 构造实例 + 整文件测，
   本 SPEC 只删 `RunState.usage` 字段，保留 `UsageSummary` 类；
3. 给后续阶段埋雷：未来谁信了 docstring 把 `state.usage` 当真相用，就会拿到 None。

## 3. 不变式 / 契约（铁律，方案必须满足）

> 「动 reducer 契约」的核心是这一节。每条都是**可被测试断言的不变式**。

### 3.0 沿用铁律（phase-3-events.md §6.0，不动）

1. **唯一真相源**：事件只写 Tape 一处。
2. **幂等性**：reducer 对同一事件应用 N 次 = 1 次（streaming text 用 `text@seq`）。
3. **一条读路径**：streaming = replay = 同一个 `apply_event`。
4. **fail loud**：未知事件 / 残行 / 损坏 / 不兼容 → 显式报错或 warning。

### 3.1 本次新增 / 强化的不变式

**I-RESUME-1（B1 核心）**：resume 永不重跑 `node_status ∈ {"done", "skipped"}` 的 node。
> 判据：replay 后任一 `node_status[N] ∈ {"done", "skipped"}` 的 N（**两类终态**，
> NEW-1），必须不出现在 `_drive_from(start_node=A, ...)` 的 dispatch 序列里。
> **`state.current_node` 不可作为 resume 唯一判据**——它在 `node_completed`/
> `node_skipped` 与 `route_taken` 之间的窗口语义模糊。
>
> **范围限定（R5）**：本不变式**仅**保证「不重跑 done / skipped 终态」。
> `node_status == "running"`（崩在 `[node_started, node_completed)` 窗口）的 node
> 会被重新 dispatch——reducer 幂等保 state 不双计，但**外部副作用可能重复**
> （at-least-once 语义，由调用方承担；见 §5.2 out-of-scope）。这是 resume 的根本
> 语义边界，**非本 SPEC 引入的新缺陷**，B1 不扩方案去解决它。

**I-RESUME-2**：resume 起点 = 「最后 done node 的下一 node」（route 求值）。
> 这是 `_next_node_for_resume` 既有契约，**只是判据要从 `current_node` 改成
> done-node 序列**。`current_node` 仅保留为诊断字段（reducer 仍维护，但 from_tape
> 不再独尊）。
>
> **现存 `current_node` 消费者清单（R7，grep 全代码库）**：
> - `orca/events/replay.py` —— reducer 写者（node_started / route_taken / workflow_completed 等）。**B1 后仍写**，仅 from_tape 不独尊。
> - `orca/run/orchestrator.py:438` —— from_tape 起点。**控制流** → B1 改读 done-node 序列。
> - `orca/run/resume.py:_detect_parallel_mid_crash:196` —— 读 current_node 判 parallel 组 mid-crash。**诊断**（崩溃现场快照），不参与控制流推进；B1 不动。
> - `orca/iface/web/*` / `orca/iface/cli/*` —— TUI / Web 渲染「当前 node」高亮。**纯诊断**。
> - `orca/run/projections.py` —— 派生视图，**诊断**。
>
> 结论：B1 后 from_tape 是唯一被切换的控制流消费者；其余全是诊断，行为不变。

**I-REPLAY-3（B2 核心）**：**光凭事件序列必须完整重建 `_drive_from` 的 `outputs_acc`**。
> 判据：`replay_state(tape)` 派生出的 `outputs_acc`（经
> `_outputs_acc_from_state` 包壳 `{node: {"output": raw}}`）必须与 live 路径在
> **同一 dispatch 步**的 `outputs_acc` 逐字段相等——包括被 skip 的 node。任何只在
> live 内存里写、reducer 不持久化的字段都是裂缝。
>
> **形状对齐（R1）**：`_outputs_acc_from_state`（resume.py:175）会对 `state.context[N]`
> 再包一层壳 `{"output": raw}`。因此 **reducer 写进 `context[N]` 的必须是 raw**
> （= None），**不是** `{"output": None, "skipped": True}`——否则 resume 路径得
> `{"output": {"output": None, ...}}`，`{{ N.output }}` 渲染为 dict 与 live 的 None 发散。
> 同理 live 路径写 `outputs_acc[N] = {"output": None}`（与 `outputs_acc` 既有约定一致），
> `"skipped": True` 标记从 `node_status[N] == "skipped"` 派生即可，不进 outputs_acc。
>
> 此不变式是 §3.4「分歧 = 错误」的具体化：reducer 必须能**单凭 tape** 重建出与 live
> 完全一致的下游可渲染上下文。

**I-REDUCER-4（B3）**：reducer 对每个 EventType 的行为必须与 docstring 一致；
schema 里的字段必须至少有一个 reducer 写入路径或显式标注「派生自他处」。
> 「约定优于文档」——schema 字段 + reducer docstring 必须二选一：真实现 或 删字段 +
> 改 docstring。**注意（R2）**：`UsageSummary` 类本身**不是死类**（`projections.node_usage`
> 用作返回类型 + 构造实例，`tests/schema/test_state.py` 整文件测它）；死的只是
> `RunState.usage` 这条**归集字段**（无 reducer 写入）。本 SPEC 只删后者，保留前者。

**I-BCOMPAT-5（向后兼容）**：**老 tape 必须能重放出新 state**——但不保证新 state
有老 tape 从未捕获的字段（B2 的 `context[N]` 在老 tape 上由 `node_skipped` 事件存在
⇒ N 被 skip ⇒ `context[N]=None` 派生）。
> 即：本 SPEC 改的是 reducer **派生**维度，不增 / 不改 EventType，不改 Event.data
> schema。老 tape 不需迁移。

### 3.2 reducer 契约的具体调整（显式列出）

| 事件 | 老 reducer 行为 | 新 reducer 行为 | 说明 |
|---|---|---|---|
| `node_skipped` | 只设 `node_status[N]="skipped"` | 同时设 `context[N] = None`（mirror `node_completed` 存 raw，skipped 时 raw=None） | **变**：补 I-REPLAY-3（R1 形状裁定） |
| `node_started` / `node_completed` / `route_taken` | 维护 `current_node` | **不变** | I-RESUME-1/2 改的是 from_tape 的**读者**，不是 reducer 写者 |
| `agent_usage` | no-op（docstring 漂移） | no-op（**docstring 改对**）+ 删 `RunState.usage` 字段（**保留 `UsageSummary` 类**，R2） | **变**：契约对齐，删顶层 RunState 死字段 |
| 其它 EventType | 不变 | 不变 | — |

### 3.3 tape 事件序列语义（不变，向后兼容性声明）

- `node_skipped` 事件的 `data` 字段**不变**（仍 `{reason: ...}`，不增 `output` 字段）。
  reducer 派生 `context[N] = None` 是**纯派生**，不进 tape。
- 老tape（含 `node_skipped` 但 reducer 老行为不写 context）重放时新 reducer 会自动补
  `context[N] = None`——「光凭事件序列重建」成立（`node_skipped` 事件存在 ⇒ N 被 skip ⇒
  raw output=None）。**老 tape 不需迁移**（I-BCOMPAT-5）。
- `agent_usage` 事件本身**不动**（translator / projections 仍消费它的
  `data.input_tokens` 等；`UsageSummary` 类保留）。删的只是**顶层 `RunState.usage`
  归集字段**。
- **`workflow_resumed.data` 增 `current_node_at_crash` 字段（R7）**：additive，
  老 reducer no-op 兼容（pydantic 默认接收未知字段或被忽略；reducer 对
  `workflow_resumed` 本就是 no-op，replay.py:224-233，无兼容风险）。

## 4. 方案（方向级，不写完整代码）

### 4.1 B1 — resume 起点改判据（NEW-1 方案 c：保留 current_node + status 双判）

**为什么第一轮方案被推翻（NEW-1）**：第一轮「完全丢弃 `state.current_node`」方案在
B1 入口引入新 P1 回归——任何 `done → skipped → crash` 序列（典型：用户显式 skip 了
B，之后崩在 C running）下，`state.current_node = B`（被 skip 的 node 的
`node_started` 之后无 `route_taken` 落盘的窗口内 reducer 维护的 current_node），而
B 的 `node_status == "skipped"` 是**终态**——重 dispatch B 等于重跑用户已显式跳过的
node，违 §0「resume 不重跑已完成节点」（skipped 也是终态）。`[node_skipped(A),
route_taken(A→B))` 窗口同理。比第一轮试图修的 `[node_completed, route_taken)` 窗口
更普遍。

**方案 c（裁定，F2 修正：直接消费 `replay_for_resume` 返回值）**：保留 `state.current_node`
作起点候选，但**用 status 终态判据兜底**——`current_node` 处于 `done` **或** `skipped`
终态时，改走 progressed-node 序列推断：

```
# replay_for_resume(tape) 已先于此返回 (state, inputs, last_progressed)（见 §4.4）
resume_node = state.current_node
cur_status = state.node_status.get(resume_node) if resume_node else None
# current_node stale 的两类窗口（reducer 维护 current_node 在 route_taken 才翻）：
#   (1) [node_completed(A), route_taken(A→B)): status==done
#   (2) [node_skipped(A),  route_taken(A→B)): status==skipped
if resume_node is None or resume_node == "$end" or cur_status in ("done", "skipped"):
    progressed = [n for n, s in state.node_status.items() if s in ("done", "skipped")]
    if not progressed:
        resume_node = wf.entry                          # 一个 node 都没完成（首节点崩溃）
    else:
        last_prog = last_progressed                     # ← F2：消费 replay_for_resume 返回值
        if last_prog is None:
            raise MidFileCorruptError(...)              # defense-in-depth（见 §7 NEW-2）
        resume_node = _next_node_for_resume(wf, last_prog, outputs_acc)
        # last_prog 是 skipped node 时 outputs_acc[last_prog]={"output":None}（B2 派生）
        # → router skip_tolerant 自动命中兜底 route（既有路径，test_skip_to_agent.py:480）
```

**关键点**：

- `done` 与 `skipped` 都是「已推进」终态，统一进 progressed 集合——这是 NEW-1 的核心
  修正。`running` / `failed` / `blocked` 不算 progressed（前者重 dispatch 由 §5.2 R5
  limitation 承接）。
- **F2**：`last_progressed` 直接来自 `replay_for_resume` 返回值（在 fold 末尾记下的
  最后一个 `node_completed`/`node_skipped` 的 node 名）；**删除** `_find_last_done_node_name` /
  `_find_last_progressed_node_name` helper（见 §4.4 F2 裁定）。
- `current_node` **不再被完全丢弃**——它仍是首选起点候选；只是当它处于终态时退化到
  progressed 序列推断。`running` 状态时 current_node 仍是起点（既有行为，承接 R5
  limitation）。

**改动点 2（NEW-6 + F5-c 快照语义）**：`workflow_resumed.data["current_node_at_crash"]`
来源显式声明 = `state.current_node`（reducer state 在 fold 末尾的字面快照）。
**F5(c) 注**：在 B1 修复窗口内（status ∈ `{done, skipped}`），`current_node_at_crash`
指向**刚 done/skipped 的节点**（= `last_progressed`），而**非**下一个将 dispatch 的
节点（后者是 `resumed_node`，由 progressed-fallback 算出）。两者在窗口场景下不同，
诊断字段记录的是 reducer state 字面值（崩在何处），控制流字段记录的是续跑起点（下一
步去哪）。`_bare_instance` 多存一字段 `_resume_current_node_at_crash`，`run_from_state`
emit `workflow_resumed` 时取用。诊断字段，不影响控制流。

**F4(b) skip 路径可复现性声明**：resume 仅能复现 **route-eval 子路径**——
`_next_node_for_resume` 用 router.resolve 重算下一 node。用户显式 `skip_target` 的
选择**若未落盘 `route_taken` 则丢失**，按 route-eval 重算（与 live skip 路径不一定
一致）。skipped-window fallback（窗口 2）需 A 有 catch-all route（`when=None`）才能
复现 live 路径——`output=None` 经 router skip_tolerant 命中兜底；若 A 无兜底 route，
resume 时会 `RouteError` → `workflow_failed{NoRouteMatch}`（fail loud，归因清晰）。
这是 skip + crash 组合的固有不可重建性，**不扩 B1 方案**（持久化用户 skip_target
选择是独立议题）。

**保留行为**：

- `workflow_resumed` 事件仍 emit（data 多 `current_node_at_crash` 一项，additive）；
- `ParallelGroupMidCrashError` 检测仍按 `node_status == "running"` 判
  （`_detect_parallel_mid_crash`），不受影响；
- `EmptyTapeError` / `AlreadyCompletedError` / `MidFileCorruptError` 全不变。

**边界**：`current_node == "$end"` 老逻辑（罕见：route_taken 已落盘到 $end 但
workflow_completed 没落盘）由 `cur_status` 检查天然覆盖——`$end` 不在 `node_status`
里，`cur_status = None`，触发 progressed 推断 → 最后一个 progressed node 的下一跳
经 `_next_node_for_resume` 算出 `$end` → drive_loop 立即退出 → emit workflow_completed。

### 4.2 B2 — skip 产出落 reducer 持久层

**改动点 1**（`orca/events/replay.py::node_skipped` 分支）：从只设 `node_status` 扩展为
同时设 `context`，**raw = None**（mirror `node_completed` 存 raw 的约定；R1 形状裁定）：

```
node_status = {**state.node_status, node: "skipped"}
context = {**state.context, node: None}
return state.model_copy(update={"node_status": node_status, "context": context})
```

**形状裁定理由**：`_outputs_acc_from_state`（resume.py:175）对 `state.context[N]` 再包壳
`{"output": raw}`；要让 resume 路径的 `outputs_acc[N] == {"output": None}` 与 live 逐字
相等，reducer 必须存 raw（= None），不能存 dict。

**改动点 2**（`orca/run/orchestrator.py:671`）：live 写法改为
`outputs_acc[current] = {"output": None}`（**去掉 `"skipped": True`**——该标记从
`node_status[current] == "skipped"` 派生即可，不进 outputs_acc，避免 live 内存里多出
reducer 不持久化的字段）。

**NEW-7 显式声明**：目前**无消费者读 `outputs_acc[node]["skipped"]`**——
grep 全代码库确认。该标记若未来需在某处区分 skipped vs done，**从 ctx 派生
`node_status[node] == "skipped"`** 即可（reducer 已持久化），不重新引入
outputs_acc 字段。本声明锁定 R1 形状不被未来消费者回潮破坏。

**F3（state.context 拓宽 blast radius certify）**：B2 把 `state.context[skipped_N]`
从「缺失」拓宽为 `None`，需确认其它读者不破。grep 确认仅 `orca/run/resume.py:175`
（`_outputs_acc_from_state`）**迭代** `state.context.items()`；其余读者（TUI / web /
projections / route 求值经 ctx）均 **keyed lookup** `state.context[node]`——keyed 得
`None` 与 keyed 得 `KeyError/Undefined` 在 StrictUndefined 下表现不同（前者返回 None，
后者 raise），但下游对 skipped node 的 keyed 访问本就期望 None（`{{ skipped.output }}`
经包壳后取 `None.output` → Jinja 容错为 None）。B2 后 keyed 得 None **无破坏**。

**NEW-E2（skip-None 与 executor 真 None 不可区分）**：B2 后 `outputs_acc[skipped]={"output":None}`
与「executor 真返 None」的 outputs_acc 形状不可区分。可接受：当前**无 executor 返
裸 None**（既有隐式契约，`orca/run/router.py:103-105` 注释假设 output 非 None 才有意义
的 when 求值）；若未来引入可能返 None 的 executor，需另加 marker（如 ctx 派生
`node_status`）区分。本 SPEC 不预防此假设场景。

**改动点 3**（测试）：`tests/run/test_skip_to_agent.py:104` 的 `| default('<skipped>')`
**保留**（用户可读性，与 B2 无关），但**新增一条不带 `| default` 的回归测试**断言
resume 后 `{{ skipped.output }}` 渲染为 `None`（不 UndefinedError）——锁定 I-REPLAY-3。

**幂等性**：`node_skipped` 事件对同一 node 多次应用 = 一次（`{**state.context, node: X}`
是覆盖语义），不违铁律 2。

**向后兼容**：老 tape（含 `node_skipped` 但 reducer 老行为不写 context）重放时新
reducer 会自动补 context——I-BCOMPAT-5 成立。

### 4.4 MINOR — from_tape 多次 tape 遍历合并（R4：4 → 2）

**实读基线修正（R4）**：`from_tape`（orchestrator.py:382-460）实际有 **4 次** tape 全量
读取，不是原 SPEC 说的 2 次：

1. `_find_first_corrupt_line(tape_path)`（:417）—— 全扫描判中段损坏；
2. `replay_state(tape)`（:424）—— fold state；
3. `_find_last_done_node_name(tape, done_nodes)`（:451，仅在窗口分支触发）—— 全扫描
   找最后 done node；
4. `_inputs_from_tape(tape)`（经 `_bare_instance`，:509）—— fold + 抽 inputs。

**改动点（F1+NEW-E1 方案 D，单 pass；推翻 rev3 的「2 次 tape.replay()」虚假承诺）**：

rev3 方案的实测 tape 读次数 = corrupt(1) + replay_for_resume 内部(2) + `_bare_instance:509`
独立调 `_inputs_from_tape`(1) = **4 次，零改进**，且 §6.4/§8.4 的 `assert call_count==1`
会必失败。F1 方案 D 重写如下：

- **第 1 次**：`_find_first_corrupt_line` 独立 raw open 扫描（严格 JSON 行级校验，与
  reducer fold 的 fail-soft 语义不同，不合并）。
- **第 2 次（单 pass fold）**：**新建 `orca/run/resume.py::replay_for_resume(tape) -> (state, inputs, last_progressed)`**
  ——run 层自含完整 fold（调 events 层**公共** `apply_event` reducer，不调 events 层
  `_replay_state_and_inputs`），在**同一 `tape.replay()` 迭代**上同时抽取 `inputs`
  （从首条 `workflow_started.data.inputs`）+ `last_progressed`（最后一个
  `node_completed` OR `node_skipped` 的 node 名）+ fold state。

  伪代码：

  ```python
  def replay_for_resume(tape):
      state = RunState(run_id=tape.run_id, ...)
      inputs = {}
      last_progressed = None
      ws_seen = False
      for event in tape.replay():                     # 单次迭代
          state = apply_event(state, event)           # events 层公共 reducer（不改签名）
          if not ws_seen and event.type == "workflow_started":
              ws_seen = True
              raw = event.data.get("inputs")
              inputs = raw if isinstance(raw, dict) else {}   # mirror _inputs_from_tape 语义
          if event.type in ("node_completed", "node_skipped"):
              last_progressed = event.node            # 一行 if，shadow-reducer tradeoff（F5-b）
      return state, inputs, last_progressed
  ```

- **新增改动点（F1）**：`_bare_instance` 签名改为**接收 `inputs` 参数**（来自
  `replay_for_resume` 返回），**不再独立调 `_inputs_from_tape`**。`from_tape` 调用链
  变为：`from_tape` → `replay_for_resume(tape)` 拿三元组 → 把 `inputs` 透传给
  `_bare_instance`。

- **events 层契约影响（NEW-E1）**：events 层 `_replay_state_and_inputs` 在 from_tape
  路径不再被调用，但仍被 in-session `step.py:472` 路径使用——**签名零改动**，保留为
  events 层公共 API。**from_tape 改走 run 层 `replay_for_resume` 自含 fold**（调 events
  层公共 `apply_event`），不破坏「events 层是唯一 fold 入口」契约（`apply_event` 仍是
  唯一 reducer，run 层只是组合它 + inputs/last_progressed 抽取）。

**F5(b) tradeoff 承认**：run 层 `last_progressed` 扫描是 shadow-reducer（events 层
reducer 已对 `node_completed`/`node_skipped` 折算进 state，run 层在同一循环顺手记
last_progressed 是冗余跟踪）。可接受：(1) 一行 `if event.type in (...)` 不破可读性；
(2) last_progressed 是 run 层概念（resume 起点），不该让 events 层 reducer 知道；
(3) shadow 仅在 from_tape 路径激活，不影响 live 路径。

**F2 helper 删除（裁定）**：删除 `_find_last_done_node_name` /
`_find_last_progressed_node_name` helper（或退化为测试辅助）。B1 直接消费
`replay_for_resume` 返回的 `last_progressed`。原 rev3 §4.4「保留该 helper 公开 API 不动」
措辞**删除**。grep 确认该 helper 既有调用方仅 from_tape（无外部消费者），删除安全。

**保留**：`_inputs_from_tape` 公开 API 不动（仍可被其它调用方使用，零调用方波及）；它
仅在 from_tape 路径被旁路（由 `replay_for_resume` 抽取 inputs 取代）。

**注**：crash resume 非热路径，性能 trade-off 非首要，但既然动 from_tape，4→2 真改进 +
依赖方向清洁是合理收尾；进一步降到 1 次（合并 corrupt 检测）会破坏严格/容错语义分离，
**不做**。

    foreach / retry 的 item/attempt 级 at-least-once 是已知 limitation。

## 7. 失败路径

| 场景 | 处理 |
|---|---|
| `_find_last_progressed_node_name` 返 None（无任何 progressed node） | 从 `wf.entry` 重跑（既有逻辑，保留） |
| **`progressed` 非空但 `_find_last_progressed_node_name` 返 None（R7 + NEW-2 defense-in-depth）** | raise `MidFileCorruptError`。**defense-in-depth**：当前 reducer 不变式下**不可达**（`state.node_status` 有 done/skipped ⟹ tape 必有对应的 `node_completed`/`node_skipped`）。保留是防未来 reducer 改动破坏不变式时静默通过——fail loud 优先于 silent corruption。 |
| `_next_node_for_resume` route 求值失败（无兜底 route） | 透传 `RouteError` → `workflow_failed{NoRouteMatch}`（既有路径，不变）。skipped 的 last_prog（output=None）由 router skip_tolerant 命中兜底 route，不走此分支。**F4(b)**：resume 仅能复现 route-eval 子路径；用户显式 `skip_target` 选择若未落盘 `route_taken` 则丢失，按 route-eval 重算；skipped-window 需 A 有 catch-all route（`when=None`）才能复现 live 路径，否则 fail loud `RouteError`。 |
| 老版本 tape：`node_skipped` 事件存在但 reducer 老行为写过 | 新 reducer 自动补 `context[N] = None`，无迁移（I-BCOMPAT-5） |
| 老版本 tape：删了 `RunState.usage` 后老代码读 `state.usage` | `run_manager` 同步切换 projections（B3 改动点 3）；其它读者 grep 确认仅 run_manager 一处 |
| `node_skipped` 同 node 多次（异常 but 可能） | reducer 覆盖语义（幂等，铁律 2 不违） |
| from_tape 在已 completed 的 tape 上跑 | `AlreadyCompletedError`（既有，不变） |
| 崩在 `[node_started, node_completed)` 窗口（node_status=running） | node 被重 dispatch（at-least-once）；外部副作用可能重复，调用方承担（§5.2 R5） |
| 崩在 `[route_taken→$end, workflow_completed)` 窗口 | resume 推进到 `$end` 但 end_route=None，final outputs fallback wf.outputs（phase-14 Route.output 不可重建，§5.2 R3 已知 limitation） |
