# Release Note —— SPEC E（单 tape 真相源裂缝：discovery legacy + handle.status hint）

**日期**：2026-08-03
**SPEC**：`docs/specs/2026-08-02-audit-e.md` rev3（round-2 review pass-after-rev3）
**分支**：`in-session-unified-backend`

## 改动总览

修 1 处真裂缝 + 1 处契约边界显式化 + 2 处 fail loud 补强，scope 局限在
`orca/iface/web/run_manager.py` 的 `discover_runs` discovery 路径（不动 events / replay /
tape 任何契约）：

1. **E-1（MAJOR）—— legacy 分支改走 `_summary_from_tape`**：
   `discover_runs` 的 legacy 分支（`~/.orca/runs/*.json` 旧 BgRunMeta）原本对每个 run
   硬编码 `status="cancelled"` / `progress="?"` / `cost=0.0` / `event_count=0`——tape
   已读到却从不 replay。现改为复用与 attached 同款的 `_summary_from_tape(tape_path, source="legacy")`
   从 tape fold 派生 status/progress/cost/elapsed/event_count。消除双派生口径（DRY +
   铁律 1 唯一真相源 + 铁律 2 一条读路径）。

2. **E-2（MINOR）—— handle.status hint 语义文档化（方向 A，零运行时代码改动）**：
   `_meta_from_handle` / `list_runs` / `discover_runs` 三个公共方法 docstring 显式标注
   `handle.status` 是**实时 hint**（非权威，权威 status 永远在 tape），emit 终态事件落 tape
   与 `handle.status` 赋值之间存在**非原子 transient 窗口**——同一 run 在「live」与「重连后
   （attached 走 tape fold）」可能 transient 不一致（设计 trade-off：实时性 > 原子性）。
   `RunMeta.status` / `RunSummary.status` 字段加行注释 `# hint: 权威在 tape`。
   in-memory 分支的 `status` / `event_count` 取 handle 字段属 C1 perf 豁免，
   `progress` / `cost` / `elapsed` 仍走 `replay_state(handle.tape)`。

3. **N1（fail loud）—— `_summary_from_tape` 内层 except 补 warn**：
   内层 `except Exception: return None`（`_scan_meta_overview_cached` 抛异常时）原本静默吞错，
   导致 AC5「warning 含 run_id + tape path」不可达（外层 `discover_runs` 的 except 永不触发）。
   补 `logger.warning("tape 概览扫描失败（视为 corrupt skip）：%s", tape_path, exc_info=True)`。

4. **AC8b（非回归守卫）—— `_meta_from_handle` replay 失败降级 warn 加 `replay-degraded` 标记**：
   原 warn 消息无稳定 grep 锚点；补 `run_id + replay-degraded` 双锚点（CI / 跨版本检测）。
   语义零改动（仍 `status = handle.status`，不抛、不静默）。

## 三条破坏性 user-facing 变更（必须声明）

### (a) legacy tape 缺失 → skip + warn（原：展示 stale 行硬编码 cancelled）

**原行为**：legacy BgRunMeta 存在但 tape 文件缺失时，仍展示一行硬编码 `status="cancelled"`
的 stale 行（status 撒谎，违反铁律 1）。

**新行为**：**legacy tape 缺失 → skip + warn**（fail loud，铁律 4）。用户在 discovery 列表
将看不到 tape 缺失的 legacy run。如需 stale 可见性，应在前端单独处理——discovery 的职责
是展示真相，不是展示 stale。

### (b) legacy `started_at` 语义迁移（spawn 时刻 → emit 时刻）

**原行为**：`started_at` 取 BgRunMeta.started_at（spawn 时刻）。

**新行为**：走 `_summary_from_tape` 后取 tape `workflow_started.timestamp`（emit 时刻）。
两者秒级差异（spawn → emit 之间有 cli 启动 / tape open 间隔），前端按 `started_at` 排序
的顺序可能变化。

### (c) crashed legacy run（tape 无终态事件）显示

**原行为**：硬编码 `cancelled`——掩盖 crash 信号（违反铁律 4）。

**新行为**：从 tape 派生 → `live-pending` / `running`（按 `_summary_from_tape` 的
`overview.run_status` 映射）。**Trade-off（接受）**：新行为可能比 `cancelled` 更误导——
用户看到 `running` / `live-pending` 可能 attach 一个实际已死 / 崩溃的 run，需手动清理。
**接受理由**：tape 真相 > 用户感知便利（铁律 1 优先），伪造 `cancelled` 违反铁律 1 且掩盖
crash 信号（违反铁律 4）。

**crashed legacy run 手动清理步骤**：
1. `rm ~/.orca/runs/<run_id>.json`（删 legacy meta）
2. `rm <tape_path>`（删 tape 文件，路径见 warning 日志）
3. 刷新 discovery 列表
