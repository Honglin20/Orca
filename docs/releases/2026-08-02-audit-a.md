# Release Note —— SPEC 2026-08-02-audit-a (stop 判 run 终态 + dupe-check tape 派生活跃性)

> spec：`docs/specs/2026-08-02-audit-a.md`（r4 conditional-pass）

## 改了什么

### 1. 新增 fail-loud 终态扫描 reader（`orca/iface/in_session/_tape_probe.py`）

纯只读、零副作用。两种失败模式显式分开（B-2）：

- 行非合法 JSON（中间残行 / 末尾 partial）→ `raise TapeParseError`（fail loud I5）。
- 合法 JSON 但 pydantic `Event` 校验失败（schema 演化）→ `logger.warning` + `continue`。

重复终态检测两套触发（B-1）：

- `terminal_count`（不去重）+ `terminal_types_seen`（去重 set）。
- 多类终态（completed+cancelled 等）→ `raise TapeContradictionError(types, last_seq)`。
- 同类重复（2× cancelled）→ warn `[AUDIT] duplicate-terminal` + 返该类型（不阻塞）。

依赖单向：仅 import `orca.schema.Event`（events→iface 合法方向）。**禁 import `orca/iface/web/`**。

### 2. `cli.py::stop`：emit 前 fail-loud 扫 tape 终态（4 分支短路）

按 spec §4.1 控制流骨架 B-5 重写：

- 拿 flock → 调 `scan_terminal`（纯只读，不开 bus）→ 分支判定。
- 分支 0：多类矛盾（`TapeContradictionError`）→ stderr + `[AUDIT]` warning log + `raise typer.Exit(1)`，不 emit。
- 分支 1：坏 tape（`TapeParseError`）→ stderr「doctor」+ `raise typer.Exit(1)`，不 emit。
- 分支 2：`workflow_cancelled`（含同类重复短路）→ `{note:"already-cancelled", status:"cancelled"}`，不 emit。
- 分支 3：`workflow_completed` / `workflow_failed` → `{note:"already-terminal", status:<type>}`，不 emit。
- 分支 4：无终态事件 → 实例化 `Tape(resume=True)` + `EventBus`，emit 一条 `workflow_cancelled`。

fd 双释放 hazard 修复（rev4 N1 / round-4 E3）：内层 finally 仅 `bus.close()`，`_release_flock(fd)` + `clear_marker(mpath)` 由外层 finally 统一兜底所有分支。

### 3. `cli.py::_find_active_run_for_wf`：tape 终态派生活跃性，marker 仅作候选索引

- sorted glob markers；> 5 个 → warn `[AUDIT] candidate-marker-flood`（不阻塞）。
- per-candidate：先 `_read_workflow_name` 比对 wf_name（防跨 wf 误判），再 `scan_terminal`。
- 异常隔离（per-candidate `try/except`，禁包循环外）：`TapeParseError` / `TapeContradictionError` → warn `[AUDIT] candidate-tape-{corrupted,contradiction}` + 跳过。
- 无终态事件 → 返该 run_id（真·活跃）；有终态 → 跳过。
- docstring 改：删「marker 存在 ≡ run 活跃」，改为「tape 终态判活跃，marker 仅索引候选」。
- **不 raise**（活动性查询本职；raise 仅留给 stop）。

### 4. 行为变化（UX）

| 场景 | 现行行为 | 改后行为 |
|---|---|---|
| 死 marker 残留（marker 在 + tape 已终态）+ bootstrap 同 wf | 拒绝建新 run | **静默建新 run**（不再依赖手动 doctor） |
| 其他 run 坏 tape + bootstrap 同 wf | silent skip | warn `[AUDIT] candidate-tape-{corrupted,contradiction}` 跳过该候选 |
| tape 已含终态 + 用户调 stop | **追加第二终态事件，污染 tape** | 短路 exit 0，不追加；`status` 字段区分 cancelled vs completed/failed |
| 坏 tape（中间残行 / 末尾 partial）+ stop | 静默追加 workflow_cancelled 到坏 tape | fail loud exit 1 + stderr |
| 多类终态矛盾（历史污染）+ stop | 静默追加第三终态 | fail loud exit 1 + `[AUDIT] tape-contradiction` warning log |
| 同类重复终态（2× cancelled）+ stop | 静默追加第三终态 | warn `[AUDIT] duplicate-terminal` + 短路 exit 0（不阻塞用户当前操作） |

## 不变式守护

- I1 终态唯一性：stop 在 tape 已含任一终态事件时不再追加（已 completed/failed/cancelled 短路）。
- I2 终态权威源在 tape：marker 残留 + tape 已终态 → 不再被误判为活跃。
- I3 stop 幂等：重复调用追加事件集 = ∅（首次已 emit 后续短路）。
- I5 fail loud：未知 / 矛盾状态显式 raise 或可观测 warn，不静默吞。
