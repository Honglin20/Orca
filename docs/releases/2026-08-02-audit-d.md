## M1 行为变更声明（必须声明）

**修复前**：`orca run` 起 run A，浏览器起并发 run B 卡 gate 永不终态 → A 终态 + 用户关 tab → 进程在
`autoexit_seconds` 秒后退出，`manager.shutdown` cancel B 的 task（撕掉 B）。

**修复后**：上述场景 `_wait_ws_autoexit` 第三条件 `not manager.has_nonterminal_inproc_runs()`
永不满足 → 进程**不自动退**（B 继续跑）。退出途径：用户手动 Ctrl-C → `manager.shutdown` 对 B
超时 cancel。

**用户感知**：长跑并发 run B 会拖住 `orca run` 进程，不会自动退。若用户依赖「主 run 跑完进程自动退」
回收资源，需手动 Ctrl-C（与 `--stay` 一致的语义边界）。
