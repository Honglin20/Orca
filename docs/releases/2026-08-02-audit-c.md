## 概述

实现 SPEC audit-c 全部 5 个聚类（C1-C5）+ Bug2 根因修复。前端是 Orca 事件链的最后一公里，原 `workflow-store.ts` 四处 loader 全是 `console.error + return` 静默吞错（违反 CLAUDE.md 规则 12 Fail loud），导致 Bug2「同 session 第二次 run 前端永久空白」。本 release 落实 fail loud 错误态 + 退避重试 + 原子提交 + INV-7 defer-RESUME + chart partition/ErrorBoundary。

## 改动点

### C1 — Loader fail-loud + 退避重试 + 并发不串话
- `workflow-store.ts`：四处 loader（`loadRun`/`loadRunWithMeta`/`loadFull`/`loadEarlierChunk`）改为：
  - HTTP 非 200 / 网络错误 / parse 失败（含 `!Array.isArray(json)`）→ 3 次指数退避（1s/2s/4s）→ 终态 `loadStatus="error"` + 写 `loadError`（INV-1 / INV-4）。
  - 退避期 `loadStatus` 保持 `loading`（BLOCKER-3），`retryCount` 进 store 驱动 reactive banner。
  - **AbortController + moduleEpoch 双校验**（B2/G2/N2/C2）：模块级 `Map<runId, InflightEntry>` + 模块级 `moduleEpoch` counter；切 run 时 `abortAllInflight` iterate 整 Map（不只是同 runId）；所有 fetch（含 retry）必带 `{signal}`；loader 闭包持 `myEpoch`，写前校验防 A→B→A 同 runId 不同实例陈旧污染。
  - 原子提交（INV-4/N5/C12）：私有 `_refoldAndCommit(state, runId, events, patch)` helper——单 `set` 同时写 `activeRunId + events + 派生 + loadStatus="loaded"`，无 half-loaded 窗口。
  - `loadEarlierChunk` 免退避（C6），失败仅 set `historyLoadError=true` + banner；同窗口节流（M14）；写时双重校验防 chunk 写污染（C2 BLOCKER）。
- `store-types.ts`：新增 `LoadError` 命名类型。

### C2 — ChartRenderer partition + ErrorBoundary
- `ChartRenderer.tsx`：新函数 `partitionCharts(groups)`——内联 cast + reject 分区（替代旧 silent filter），输出 `valid: {identity, payload}[] + rejected: {seq, group}[]`；rejected > 0 时显示 `chart-schema-warning`（INV-5 schema 漂移显形）。
- `ChartGroup.tsx`：签名改为 `{identity, payload}[]`，`key={chart.identity}`（E3/BLOCKER-1）。
- 无 title chart dev warn-once-per-identity（MINOR-5）：模块级 `Set<identity>` 防 spam，`unloadRun` 清。
- `ChartErrorBoundary.tsx` 新文件：包在 `LazyChartWidget` 内、`ChartWidget` 外（M16）；recharts 抛错兜底（INV-6）。

### C3 — dev-mode apply-twice-compare-state canary
- `workflow-store.ts`：导出 `__foldTwiceForInvariantCheck(event)`——apply 同一 event 两次比较派生快照，任何变化 = handler 非幂等 = warn。漂移 canary 非证明全幂等（G3）；prod no-op（N3）。
- `foreach_item_completed` silent skip → `console.warn` + 保留原 progress 值（M4）。

### C4 — seq 去重 O(1) Set
- `workflow-store.ts`：`enableMapSet()`（B1）+ `seenSeqs: Set<number>`；`processEvent` 入口 O(1) `has` 查；refold 末尾重建（N1）；删旧 `events.some` O(N) 扫描（INV-3 长 run 不卡）。

### C5 — INV-7 拒收 + defer-RESUME（E1 BLOCKER）
- `workflow-store.ts`：`processEvent` 入口 `loadStatus !== "loaded"` → drop + warn-once（模块级 `Set<runId::seq>`，E6）；`unloadRun` 清此 Set。
- `use-websocket.ts`：listener 在 useEffect 顶层注册一次（BLOCKER-2，非 onopen 内防累积），订阅 store `loadStatus` 翻转——首次到 loaded 时 fire `sendResume(since=lastSeqSeen)` + one-shot `unsub()` 自清（A4）；server `_handle_resume` 重放 `seq>since` 补全 `(fetch_commit, sendResume_send]` 窗口。
- **per-socket `resumeSent` dedup**（MAJOR-2）：onopen 与 listener 共用，防同 socket 双 fire → server cancel-race；reconnect 随新 socket 重置。
- **onopen 读 `loadStatus` 分支**（BLOCKER-1）：loaded/error → 立即 sendResume；loading/idle → 等回调。
- **loadStatus 优先于 wasReconnect**（F1）：reconnect onopen 先读 loadStatus——loaded/error → sendResume + sendSubscribe 双发（MAJOR-3 reverse A5，保 server-restart 韧性）；loading/idle → 不双发，走 listener 路径。
- **listener fire 后 arm resume watchdog**（M3）：兜底 server 在 loading 期重启 short-circuit 的极端边缘。
- public `loadFromEvents` 不 touch loadStatus（E7/C10）：triggerResumeFallback 专用。

### UI

- `RunLoadError.tsx` 新文件：`data-testid="run-load-error"` 显示错误码 + 失败原因 + 重试按钮 + 返回列表。
- `retry-banner`：loading+retryCount>0 叠加（BLOCKER-3）。
- `use-run-events.ts`：docstring 更新（重试入口 = store action + UI 按钮）。
