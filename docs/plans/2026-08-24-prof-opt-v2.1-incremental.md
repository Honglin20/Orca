# prof-opt v2.1 incremental implementation plan

Date: 2026-08-24
Status: in progress

## Problem

The shipped `prof-opt` workflow (v3.5) is a sound latency/accuracy gate, but it
optimizes from a narrow activation/normalization/relocation playbook and its
baseline is a single short-budget accuracy point.  It cannot answer “why did
this candidate fail and what should the next proposal exploit?”, and it does not
consume a full baseline learning curve.  The workflow also keeps an agent shell
around a deterministic gate although the engine now supports script nodes.

## Scope for this increment

This is an incremental v2.1, not a full DAG rewrite.  It keeps the proven
shadow, contract, profiling, and round-advance machinery while adding the
missing general optimization loop:

1. **Reusable metric-curve comparison**
   - Add `metric_curve.py`: parse epoch metrics from a training log, persist
     monotonic JSONL curves, and compare a candidate curve against the baseline
     at the same epoch with metric-direction normalization.
   - The same script is the only coarse/fine-grained comparison primitive.

2. **Auditable experiment memory**
   - Add `experiment_ledger.py`: summarize every proposal/version into one
     `experiment_ledger.json` plus `experiment_summary.md`.
   - Each row records the change, predicted and measured latency, prediction
     error, accuracy result, verdict, and a deterministic next-step hint.
   - `po_propose` must read this ledger before proposing; the ledger is the
     explicit answer to repeated proposals and vague history.

3. **Wider, evidence-ranked proposal space**
   - Extend the playbook with general from-scratch SOTA structure levers
     (deeper-narrower, shallower-wider, low-rank projection, linear attention,
     and module fusion/reshaping), all gated by measured bottleneck patterns.
   - Proposals must state expected accuracy impact, confidence, evidence, and
     SOTA references; ranking is Pareto-aware rather than latency-only.

4. **Deterministic gate**
   - Convert `po_gate` from an agent wrapper to a `kind: script` node.

5. **Web/report visibility**
   - Keep static HTML charts as portable artifacts and add a machine-readable
     `dashboard.json` that the Web shell or any static viewer can consume.

## Explicit non-goals in this increment

- No project-specific branches or model-family names in executable logic.
- No attempt to invent per-epoch formats at comparison time; the contract must
  expose an epoch metric pattern or the curve gate fails loudly.
- No replacement of `mfu_benchmark.py`: it remains the sole latency authority;
  the existing placeholder can be swapped without changing consumers.

## Verification

- Unit-test curve parsing/comparison, ledger summarization/hints, and script
  gate routing/compilation.
- Run the prof-opt-related tests and workflow validation.
- Re-read every edited prompt for prompt-cleanliness and fail-loud behavior.
